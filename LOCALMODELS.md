# Local AI & The Intelligence Layer\n\nPromptium operates on a hybrid intelligence architecture. Unlike standard extensions that rely predominantly on off-site telemetry pipelines or offloading complete conversational histories to external GPU instances, Promptium enforces a local-first operational philosophy.\n\nThe extension utilizes embedded local models, selective API integrations, and robust deterministic fallbacks to optimize latency, cost-efficiency, and data privacy.\n\n---\n\n## Local Retrieval Pipeline (`Transformers.js`)\n\nPromptium executes Semantic Search and AI similarity ranking utilizing an optimized, in-browser transformer model.\n\n*   **Functionality**: When executing queries (e.g., "creative writing patterns") within the prompt library, Semantic Search correlates entries by contextual meaning rather than relying on explicit keyword token matching.\n*   **Execution Runtime**: The extension deploys a highly quantized WebAssembly model (`Xenova/all-MiniLM-L6-v2`) directly within the browser execution context.\n*   **Privacy Model**: Semantic retrieval vectorization and classification are executed entirely on-device. No prompt data or telemetry is transmitted externally during this operation.\n\n### Local Model Download Management\nUsers maintain explicit granular control over local models via the dedicated Settings UI. The interface provides status indicators, manual initiation protocols for model downloading, and clear visualization of active storage requirements, ensuring transparency over the `transformers.js` instantiation.\n\n### Deterministic Fallback Behavior\nIn environments natively lacking optimal WebAssembly support or during failed model instantiation, Semantic Search degrades securely to classic deterministic exact-keyword matching formats. This prevents rendering blockages and maintains consistent UI availability without generating critical execution errors.\n\n---\n\n## Remote Inference Integration (Gemini API)\n\nPromptium optionally integrates the Google Gemini API to drive the **Improve Prompt** optimization flow.\n\n*   **Functionality**: Evaluates an existing user prompt and structurally enhances it into a more precise, explicit, and instruction-optimized schema suitable for advanced LLM interactions.\n*   **Authorization Control**: Execution strictly requires the user to provision a personal API Key via the global Settings interface to authorize requests.\n*   **Execution Topology**: \n    1.  The UI sanitizes and packages the prompt payload.\n    2.  The payload is routed to the `utils/ai-bridge.js` handler.\n    3.  Data is relayed to the Background Service Worker to bypass cross-origin restrictions securely.\n    4.  A direct parameterized request is dispatched to the `generativelanguage.googleapis.com` endpoint.\n    5.  The UI provisions a Diff Review overlay, displaying a granular comparison between the original prompt and the AI-generated structural improvements.\n\n*Error State Handling: In scenarios where an API key is unassigned, invalid, or the endpoint is inaccessible (due to localized network proxies or service outages), the Improve Prompt mechanism fails gracefully, surfacing explicit UI feedback structures outlining the specific failure modality.*\n\n---\n\n## Deterministic Execution Logic\n\nThe overwhelming majority of Promptium\'s core functionality executes via highly optimized, deterministic JavaScript logic, entirely circumventing the latency of black-box AI inferences:\n\n*   **Template Parsing & UI Generation**: Parsing variables (e.g., `[label]` and conditional `[label?]` syntax), backwards compatibility normalization for legacy bracket formats, and dynamic form construction.\n*   **Export Pipeline & Orchestration**: Comprehensive Document Object Model (DOM) to Markdown transformation, HTML scraping, Notion/Obsidian structurally wrapping, and deterministic filename generation executed predictably inside the `utils/exporter.js` handler.\n*   **Cross-LLM Interoperability**: Scraping the source chat context, estimating token constraints, and appending context cleanly formatting payloads when executing Cross-LLM Continuation (`Continue On`).\n*   **State Bookmarking**: Generating cryptographic consistency hashes, resolving URIs natively within text formats, and applying specific highlight or bookmark schema markers (`⭐`).\n\n## Local Rendering Engine\nThe local rendering abstraction layer (`utils/export-preview-renderer.js`) guarantees that preview generation for formatted outputs (Markdown, mapped Notion exports, localized PDF representations) executes strictly client-side. Operations adhere flawlessly to defined Extension Content Security Policies (CSPs) without executing unverified external network calls for asset injection.\n
